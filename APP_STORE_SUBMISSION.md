# App Store Submission Checklist

Tracks the items needed to submit ShiftSync 1.0. Items marked `[x]` are done in the codebase; items marked `[ ]` require action in App Store Connect / hosting, which can't be automated from the repo.

## 1. Legal Requirements & Disclaimers

- [x] **Terms of Use** — in-app screen (Profile → Legal → Terms of Use) stating ShiftSync is an informational tool only, the user is solely responsible for verifying pay/shift accuracy, and the developer assumes no liability for payroll errors or employment disputes.
- [x] **Privacy Policy** — both an in-app screen (Profile → Legal → Privacy Policy) and a standalone `PRIVACY_POLICY.md` ready to host, declaring all data (shift history, geofence coordinates) stays local with zero tracking or transmission.
- [x] **PDF report disclaimer** — every exported PDF timesheet now includes the footnote: *"This report is a personal record generated by the employee and does not constitute an official payslip or legal document."* (`ExportView.swift`)
- [x] **Copyright notice** — "© 2026 ShiftSync. All rights reserved." plus the app version, shown at the bottom of Profile settings.

## 2. Privacy & App Store Declarations

- [x] `NSLocationWhenInUseUsageDescription` / `NSLocationAlwaysAndWhenInUseUsageDescription` / `NSLocationAlwaysUsageDescription` — state location is used strictly for a local geofence to power clock-in/out reminders, and stays on-device.
- [x] Privacy Manifest (`ShiftSync/PrivacyInfo.xcprivacy`) — declares no tracking, no collected data types, and `NSPrivacyAccessedAPICategoryUserDefaults` (reason `CA92.1`).
- [ ] **App Store Connect → App Privacy**: manually declare **"No, we do not collect data."** This is a form in App Store Connect, not settable from Xcode.

## 3. Local Data Backup & Persistence

- [x] Confirmed all app data lives in `UserDefaults.standard`, included in standard iOS backups (iCloud/Finder) by default — no exclusion flags set.
- [x] **Manual JSON Export/Import** — Profile → Security & Privacy → "Export Backup (JSON)" / "Import Backup". Lets users carry shift records to a new device without relying on a full system backup (`ShiftStore.exportBackupData()` / `importBackupData()`).

## 4. First-Time Submission Requirements

- [x] `PRIVACY_POLICY.md` drafted at the repo root. **Action needed:** replace the placeholder contact email, publish it (e.g. GitHub Pages), and paste the URL into App Store Connect → App Information → Privacy Policy URL.
- [ ] **App Review Notes** — paste this into App Store Connect → App Review Information → Notes:

  > ShiftSync runs entirely offline. There is no backend server, no account creation or sign-in, and no data collection of any kind — all shift, pay, and settings data is stored locally on the device via UserDefaults. The optional workplace location feature (used only for arrival/departure shift reminders) processes location entirely on-device and never transmits it anywhere. No demo login or test credentials are required to review the app — tap "Continue as Guest" on first launch.

- [ ] **Pricing Tier** — set to Free (Tier 0) in App Store Connect → Pricing and Availability.

## 5. Versioning & Source Control

- [x] Committed and tagged `v1.0.0-rc1`, pushed to `origin/main`.
- [ ] After this round of legal/accessibility additions, commit again and consider a new tag (e.g. `v1.0.0-rc2`) before the final Archive.

## 6. Accessibility

- [x] Added `accessibilityLabel`s to icon-only buttons app-wide (tab bar, back button, month navigation chevrons, all +/- steppers, notification bell, map search-clear button).
- [ ] **Dynamic Type** — not implemented. The app's custom design system uses fixed `.font(.system(size:))` values throughout rather than scalable text styles; adopting Dynamic Type would mean re-tuning layouts across every screen and was out of scope for this pass. Flag if you want this tackled as a dedicated follow-up.

## 7. Deferred to Roadmap (not built this round)

- Live Activities / Dynamic Island (real-time shift + earnings on Lock Screen)
- Home Screen widgets (one-tap clock in/out, weekly earnings)

Both require a new Widget Extension target and an App Group entitlement to share state with the main app — a real architectural change, not a quick edit. See README → Roadmap.
